# Примеры форматов

Эти файлы показывают целевой контракт первой версии ядра по решениям из `functional.md`. Это не реализация и не тестовые fixtures, а плановые примеры для согласования схем.

## Файлы

- `build.toml` - пользовательское намерение сборки рабочего окружения. Может быть полностью описано вручную и использовано для формирования lock.
- `build.lock.toml` - конкретная рабочая конфигурация сборки окружения. Не содержит команду запуска, output rules и publish target.
- `rules.json` - версионированный файл правил для маппинга code/input files и классификации outputs.
- `run.toml` - пользовательское намерение запуска подготовленного рабочего окружения. Команда запуска не входит в build lock.
- `publish.toml` - пользовательское намерение публикации результата. Target публикации не входит в build lock и run config.
- `publish.lock.toml` - конкретная конфигурация публикации. Для SVN содержит разрешенную числовую ревизию вместо `HEAD`.
- `manifest.json` - пример финального manifest после успешной публикации.

## Ключевые границы

- `build.toml` не входит в manifest как источник воспроизводимости.
- `build.lock.toml` описывает только сборку окружения.
- `run.toml` описывает только запуск. `run.executable` обязателен; классификация файлов по категориям выполняется после run перед публикацией.
- `publish.toml` описывает только публикацию. Классификация outputs берется из manifest, сформированного после run; `publish.toml` не содержит `output_rule_set`.
- `publish.toml` не содержит `dry_run`: preview/dry-run задается отдельным флагом при вызове Python API публикации.
- В source/target для `local` используется только `path`; для `svn` используются `location`, `path`, `revision`.
- В `publish.toml` SVN `revision` может быть `"HEAD"` или отсутствовать; в `publish.lock.toml` revision всегда конкретное число.
- `publish.toml` может содержать несколько `[[targets]]`; каждый target указывает свой список `rule_sets`, например outputs в SVN, logs в локальную директорию.
- `publish.toml` содержит один `[service_target]`; только туда публикуются manifest, lock-файлы, frozen inputs и snapshots. Пути внутри служебной зоны задаются конфигом приложения, не пользовательским publish-файлом. Пользовательские `[[targets]]` нужны для outputs/logs/temp.
- Правила опциональны для расчетного кода и inputs. Если `rule_set` не указан, соответствующая директория копируется как есть с сохранением относительных путей.
- `[rules.source]` нужен только если хотя бы один `rule_set` указан в `build.toml`.
- В `build.lock.toml` нет `copy_mode`: наличие `rule_set` означает применение правил, отсутствие `rule_set` означает копирование всей директории как есть.
- В `build.lock.toml` нет `rule_applications`: применения правил выводятся напрямую из `code.rule_set` и `inputs[*].rule_set`.
- Publish request/config отделен от lock.
- Frozen inputs публикуются в `_calcchain/frozen_inputs/`.
- Manifest публикуется последним в `_calcchain/manifest.json`.
