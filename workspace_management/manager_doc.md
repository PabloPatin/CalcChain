модуль `workspace_management` выполняет роль посредника между пользователем и рабочим пространством.

> [!note]
> Рабочее пространство (workspace) - папка на диске компьютера, 
> в которой производятся вычисления при помощи расчётных кодов.
> Рабочее пространство должно быть создано пользователем и не содержать в себе никаких объектов, 
> кроме файла config.toml на момент инициализации.
>
> В аргументах функций и классов этого модуля принято сокращать workspace до ws.

# class WorkspaceManager(ws_path, dry_run=False, auth_callback=None)

Класс `WorkspaceManager` предназначен для управления рабочим пространством и предоставляет следующий функционал:

* Загрузка исполняемых файлов расчётного кода
* Загрузка исходных данных для расчётного кода
* Отслеживание изменений в исходных и исполняемых файлах
* Выгрузка результатов работы расчётного кода

При инициализации, `WorkspaceManager` принимает следующие аргументы:

* `ws_path` - Путь до папки рабочего пространства. (Важно! Папка должна содержать ***только*** файл `config.toml`)
* `dry_run` - True - включить режим dry_run. В этом режиме в рабочее пространство не вносится никаких изменений, 
но вся информация по прежнему попадает в консоль.
* `auth_callback` - Функция обратного вызова для авторизации.

## Атрибуты и методы

### WorkspaceManager.initialize_ws(dry_run=False)

Метод для инициализации рабочего пространства. Выполняет следующую последовательность действий:
1) Проверяет, что в рабочей пространстве нет лишних файлов и папок.
2) Считывает файл `config.toml`
3) Согласно конфигурационному файлу загружает исполняемые файлы (методом `load_exec`)
4) Согласно конфигурационному файлу загружает исходные данные (методом WorkspaceManager.load_data)
5) Создаёт файл `config.lock.toml` на основе конфигурационного файла
6) Вычисляет контрольные суммы для всех файлов (файлов конфигураций, исходных данных, исполняемых)
7) Записывает информацию о рабочем пространстве в файл `info.json`

Если метод вызван в режиме dry_run, то выполняет шаги 1-4, но не сохраняет файлы в рабочее пространство.

### WorkspaceManager.set_credentials(credentials)

Устанавливает параметры авторизации для определённых ресурсов.
В качестве параметра `credentials` ожидает получить словарь следующего вида:
```json
{
  "source_address": {
    "login":  "example",
    "password": "1234"
  }
}
```

Где `source_address` - url или путь к источнику, требующему аутентификации;

> [!note]
> Количество и названия параметров должны совпадать с теми, которые требует ресурс

### WorkspaceManager.get_credentials() -> dict

Возвращает словарь со всеми сохранёнными данными авторизации.

### WorkspaceManager.read_toml_config(config_file, config_cls=None) -> dict | ConfigInterface:

Загружает конфигурацию из файла формата [TOML](https://toml.io/en/) и, 
если необходимо, распаковывает её в конфигурационный датакласс.

* `config_file` - Путь к конфигурационному файлу
* `config_cls` - Конфигурационный датакласс для распаковки (вернёт словарь, если не указан)

### WorkspaceManager.load_exec(dst_path=None, config=None) -> ConfigInterface

Метод, предназначенный для загрузки исполняемых файлов в рабочее пространство. 

* `dst_path` - Путь в рабочем пространстве, куда необходимо загрузить файлы (создаст папки, если путь не существует).
По умолчанию - корень рабочего пространства.
* `config` - Конфигурация загрузчика в виде словаря (см. раздел *Конфигурация загрузчика*). 
По умолчанию используется конфигурация, загруженная из файла `config.toml`

Для того, чтобы метод правильно отработал, в модуле `file_handlers` (в файле \_\_init\_\_.py) должен быть импортирован класс, унаследованный от `BaseLoader` у которого в качестве атрибута `type` указано то же значение, что и в `config` (см. раздел `Загрузчики файлов`).

### WorkspaceManager.load_data(dst_path=None, config=None) -> ConfigInterface

Метод, предназначенный для загрузки файлов исходных данных.
Принимает те же аргументы, что и load_exec, однако `config` для этого метода является списком конфигураций загрузчика.

Загрузка данных осуществляется в соответствии с наборами правил.

### WorkspaceManager.hash_ws_files()

Метод, который хэширует все файлы, находящиеся в данный момент в рабочем пространстве, и записывает их контрольные суммы в атрибут `WorkspaceManager.info`

Необходимо выполнять после загрузки всех исходных данных и исполняемых файлов, для последующей проверки целостности.

### WorkspaceManager.hash_file(file) -> str

Хэштрует один файл и возвращает его хэш в виде строки.

### WorkspaceManager.hash_dir(dir_path)

Хэштрует рекурсивно все файлы в папке по пути `dir_path`, и записывает их контрольные суммы в атрибут `WorkspaceManager.info

### WorkspaceManager.lock_config()

Сохраняет атрибут `WorkspaceManager.config` в файл `config.lock.toml`.

### WorkspaceManager.save_ws_info()

Сохраняет атрибут `WorkspaceManager.info` в файл `info.json`.

### WorkspaceManager.save_ws_info()

Загружает данные из файла `info.json` в атрибут `WorkspaceManager.info`

### WorkspaceManager.check_hashes()

Сверяет хэши файлов с хэшами из атрибута `WorkspaceManager.info`. Возвращает список файлов, которые были изменены.

### WorkspaceManager.record_results(dry_run=False):

Метод, который осуществляет выгрузку результатов расчёта.
Реализует следующий функционал:

1) Считывает файл `recorder_config.toml` из корня рабочего пространства
2) Проверяет, тип ресурса, на который производится выгрузка (версируемый или нет)
3) Если ресурс версируемый, то проверяет, что все исходные данные взяты с версируемых ресурсов, и не изменены после выгрузки.
4) Согласно конфигурационному файлу выгружает результаты расчёта.

Если метод вызван в режиме dry_run, то выполняет шаги 1-3 и проверит доступ к ресурсу (файлы выгружены не будут).

Детали выгрузки реализованы в классах, унаследованных от `BaseRecorder`.

### WorkspaceManager.check_results()

Метод, который проверяет допустимость выгрузки результатов в версируемый источник.

## Классы конфигураций

Все классы конфигураций принадлежат типу `ConfigInterface` (см. раздел *Конфигурационные датаклассы*).

Вот какие конфигурации принимает на вход `WorkspaceManager` в зависимости от параметров запуска:
* `class InitialConfig` - конфигурация для инициализации рабочего пространства. Содержит в себе две конфигурации для классов загрузчиков (унаследованных от `BaseLoader`): `exec` и `data`.
* `class RecordingConfig` - конфигурация для выгрузки результатов расчёта. Содержит в себе одну конфигурацию для класса-наследника `BaseRecorder` - `result`.

## Авторизация

Часть ресурсов, указанных в конфигурации в качестве источника для 
загрузки/выгрузки данных могут потребовать авторизации.
Класс WorkspaceManager поддерживает 2 варианта авторизации.

### Прямая установка параметров авторизации

В том случае, если заранее известно, какие параметры авторизации нужны каждому из источников, можно задать их напрямую.
Это можно сделать с помощью метода `WorkspaceManager.set_credentials`.

### Авторизация через callback

Альтернативный метод авторизации. Для того, чтобы его использовать, нужно передать в конструктор `WorkspaceManager` 
функцию обратного вызова, как параметр `auth_callback`.
Функция обратного вызова срабатывает в случае, если было вызвано исключение AuthorizationError 
после попытки доступа к одному из ресурсов.

На вход функция получает 2 позиционных аргумента:
  * `source_address` - адрес источника (`str`)
  * `required_params` - запрашиваемые параметры для авторизации (`list[str]`)

Функция должна вернуть словарь со всеми параметрами авторизации, 
вида `{'param 1': 'value 1', 'param 2': 'value 2', ...}`.

# Конфигурационные датаклассы

Весь функционал, связанный с конфигурационными датаклассами, находится в файле `simple_config.py`

Конфигурационный датакласс - класс, обёрнутый декоратором `@config`. 
Конфигурационный датакласс принимает на вход словарь и автоматически распаковывает его по своим типизированным полям.


Для того, чтобы преобразовать конфигурационный датакласс в словарь, 
следует пользоваться встроенным в него методом `to_dict()`

```python3
from simple_config import config

@config(partial=True)
class Data:
    name: str
    value: int

data = Data({'name': 'example', 'value': 10, 'value2': 12.5})

# Доступ к значениям через аттрибуты
print(data.name)
# example

# Значения, не указанныне в классе попадают в extra_configs (если partial=True)
print(data.extra_configs['value2'])
# 12.5

# Преобразуется в словарь (в нём нет extra_configs)
data.to_dict()
# {'name': 'example', 'value': 10}
```

* Если в словаре не указано одно из полей без значения по умолчанию - вызывается исключение LostConfigsError
* Если тип значения в словаре не совпадает с указанным в датаклассе - вызывается исключение ConfigTypeError
* Если в словаре есть значение, которого нет в датаклассе - вызывается исключение ExcessParamsError 
(можно отключить, передав параметр `partial=True` в декоратор, тогда лишние значения попадут в `extra_configs`)

## class ConfigUnion(config, \*\*config_classes)

`ConfigUnion` - класс для объединения конфигационных датаклассов. Удобно использовать, когда один словарь необходимо распаковать по 2 и более датаклассам.

```python3
from simple_config import config, ConfigUnion

@config
class ConfigOne:
    name: str
    value: float

@config
class ConfigTwo:
    time: int

merge = ConfigUnion(
{'name': 'example', 'value': 12.5, time: 0}, 
one=ConfigOne, 
two=ConfigTwo,
)
# Можно получить каждый класс через аттрибуты
print(type(merge.one))
# <class ConfigOne>

# Или обратиться к аттрибутам объединённых классов напрямую
print(merge.name)
# example

# А так же - преобразовать в словарь
print(merge.to_dict())
# {'name': 'example', 'value': 12.5, time: 0}
```

Все конфигурационные датаклассы и объединения наследуют абстрактный класс ConfigInterface.

# class BaseFileHandler(configs , \*, credentials=None, try_save_credentials=False)

Абстрактный класс-родитель, для всех классов, взаимодействующих с файлами.
Обязан иметь следующие переменные класса:
* _type - тип источника, с которым работает
* _config_cls - класс конфигурации для данного источника (Конфигурационный датакласс)

При инициализации распаковывает `configs` в свой `_config_cls` и устанавливает значение параметра `credentials` в качестве приватного атрибута.
Устанавливает `try_save_credentials`, в качесвте аттрибута, можно использовать в загрузчиках для встроенного сохранения данных авторизации
